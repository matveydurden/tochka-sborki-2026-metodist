# Методист

Концепция ИИ-помощника методиста для продуктового хакатона **«Точка сборки»**, 13–31 октября 2026 года.

**Команда «Пхукетская»:**

- Захар Толошный — участник, [@xzx-xzxx](https://github.com/xzx-xzxx).

## Задача

Кейс № 1 — **«ИИ-агент для создания образовательных программ»**. Кейсодатели — Академия цифрового развития и GigaCowork; инфраструктура — Cloud.ru.

Методист описывает курс и прикладывает референсы. Сервис уточняет требования, предлагает каркас программы и после согласования готовит связанные учебные материалы. Проверяет распределение часов, покрытие результатов обучения, полноту разделов и источники. Итоговый комплект проверяет и утверждает человек.

Планируется поддержка программ повышения квалификации, включая стажировки, и общеразвивающих программ по ИТ-направлениям, с выгрузкой DOCX, PDF, PPTX и JSON.

## Статус

Локальное приложение с Python-бэкендом и SQLite. Фронтенд сохраняет согласованную компоновку: материалы слева, параметры и диалог справа. Подключён командный OpenAI-совместимый шлюз хакатона; также поддерживается прямой Foundation Models API Cloud.ru.

## Запуск приложения

Нужен Python 3.10 или новее. Установка runtime-зависимостей не требуется:

```sh
cp .env.example .env
# Заполните LLM_API_KEY локально в .env
python3 -m backend.server
```

Открыть [локальное приложение](http://127.0.0.1:4173). Эквивалентная команда из `frontend/`: `npm start`. Сервер слушает только `127.0.0.1`; внешнее размещение и авторизация пользователей не настроены.

`.env` содержит `LLM_API_KEY`, `LLM_BASE_URL` и `CLOUDRU_MODEL`. Для командного шлюза базовый URL — `https://hub.gigaschool.ru/api/v1/llm/v1`, модель — `GigaChat/GigaChat-3-Pro`. Значение ключа не передаётся в браузер, экспорт или API-статус. После изменения `.env` перезапуск не нужен: конфигурация перечитывается сервером. Не коммитьте `.env`.

Для прямого Cloud.ru: `LLM_BASE_URL=https://foundation-models.api.cloud.ru/v1`, `CLOUDRU_MODEL=Qwen/Qwen3.6-35B-A3B`; ключ задаётся через `LLM_API_KEY` либо `CLOUD_RU_FOUNDATION_MODELS_API_KEY`. Поддерживаются только явно разрешённые адреса сервисов, перенаправления запросов с ключом отключены. Контракт прямого API: [документация Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__specs).

База создаётся в `.local/metodist.sqlite3`, вне Git. Путь можно изменить: `python3 -m backend.server --db /absolute/path/courses.sqlite3 --port 4173`. Для резервной копии остановите сервер и скопируйте файл базы. Запускайте один экземпляр сервера на одну базу.

## Основной сценарий

1. «Новая» → название, аудитория, тип и 16–500 часов. Создаётся отдельный сохранённый черновик; старые программы доступны в «Мои программы».
2. «Сформировать каркас» или запрос в чате → цель, результаты обучения и модули. Ответ модели хранится как предложение; до принятия курс не меняется.
3. Просмотреть и применить пакет. Проверить часы и нажать «Согласовать каркас». Сервер проверяет этот переход отдельно от интерфейса.
4. «Подготовить материалы» → сервер готовит каждый модуль, затем предлагает весь комплект одним пакетом: краткое содержание, тесты с ключами, задания с критериями и текстовые слайды. Объём содержания ограничен для первого рабочего прогона; это не готовые полноценные лекции. Применение атомарное.
5. Редактировать материалы вручную или запросить связанный пакет правок в чате. Принятые ручные правки сохраняются; несохранённые поля редактора защищены от случайного переключения. Изменение структуры снимает согласование и помечает прежние материалы как требующие обновления, сохраняя их текст.
6. «Экспорт» → DOCX всего комплекта, JSON сохранённой версии или печать текущего материала в PDF через браузер.

Адрес `?course=<UUID>` открывает конкретную программу после перезагрузки. Статус фонового запуска и готовое предложение восстанавливаются. Перезапуск сервера переводит незавершённые запуски в ошибку, сохраняя курс. История чата между загрузками не сохраняется; сохраняются курс, предложения и состояния запусков.

При конфликте версий сервер отвечает 409 и не затирает более свежие данные. При недоступности сервера правки остаются в текущей вкладке: доступны повторное сохранение, резервный JSON и явное открытие сохранённой версии. Не закрывайте вкладку до сохранения или скачивания правок.

Ошибки ключа, лимита, сети, JSON, часов или полноты ответа модели не изменяют курс. У каждого запуска есть идентификатор; повтор того же запроса возвращает тот же запуск. Повторная попытка после ошибки — новый явный запуск, без автоматического повтора платных вызовов. Одновременно допускается один запуск на курс.

## Ограничения первой версии

- DOCX использует базовую структуру; соответствие двум официальным шаблонам АЦР ещё не реализовано.
- Поддерживается проверка суммы часов, заполненности каркаса, структурной полноты материалов и устаревания связанных материалов. Покрытие каждого результата обучения и предметная корректность пока не подтверждаются автоматически.
- Источники не ищутся и не верифицируются. В DOCX это явно отмечено; реквизиты приказов и подписи не заполняются.
- PDF/DOCX/TXT можно прикрепить только локально, до 20 МБ на файл. Файлы не читаются и не передаются модели; вложения не сохраняются между загрузками.
- Слайды представлены как редактируемый текст; экспорт PPTX ещё не реализован.
- Это однопользовательская локальная версия. Публичный деплой, роли, защита многопользовательского доступа и соблюдение эксплуатационных требований кейса требуют отдельного этапа.
- Показатели качества и времени в продуктовом брифе остаются целями пилота, а не подтверждёнными характеристиками.

## Проверка

```sh
python3 -W error::ResourceWarning -m unittest discover -s backend/tests -v
cd frontend
npm test
npm run check
```

Бэкенд-тесты используют временную SQLite и контролируемый тестовый генератор: проверяют сохранение и повторное открытие, конфликты, старые ответы, согласование, атомарный пакет, недоступный ключ, неполные ответы, повтор запросов, восстановление запусков, HTTP Origin и экспорт OOXML. Они не подменяют проверку реального шлюза и браузерного сценария. Настоящая генерация вызывается только явным действием пользователя.
