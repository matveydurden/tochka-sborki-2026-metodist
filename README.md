# Методист

ИИ-помощник методиста для продуктового хакатона **«Точка сборки»**, 13–31 октября 2026 года.

**Команда «Пхукетская»:**

## Задача

Кейс № 1 — **«ИИ-агент для создания образовательных программ»**. Кейсодатели — Академия цифрового развития и GigaCowork; инфраструктура — Cloud.ru.

Методист описывает курс и прикладывает референсы. Сервис уточняет требования, предлагает каркас программы и после согласования готовит связанные учебные материалы. Проверяет распределение часов, покрытие результатов обучения, полноту разделов и источники. Итоговый комплект проверяет и утверждает человек.

Планируется поддержка программ повышения квалификации, включая стажировки, и общеразвивающих программ по ИТ-направлениям, с выгрузкой DOCX, PDF, PPTX и JSON.

## Статус

Локальное приложение с Python-бэкендом и SQLite. Фронтенд сохраняет согласованную компоновку: материалы слева, параметры и диалог справа. Подключён командный OpenAI-совместимый шлюз хакатона; также поддерживается прямой Foundation Models API Cloud.ru.

## Запуск приложения

Нужен Python 3.10 или новее. Зависимости форматов: pypdf, python-docx, python-pptx (зафиксированы в requirements.txt):

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# Заполните LLM_API_KEY локально в .env
.venv/bin/python -m backend.server
```

Открыть [локальное приложение](http://127.0.0.1:4173). Эквивалентная команда из `frontend/`: `npm start`. По умолчанию сервер слушает только `127.0.0.1`. Режим публичного демо описан ниже.

`.env` содержит `LLM_API_KEY`, `LLM_BASE_URL` и `CLOUDRU_MODEL`. Для командного шлюза базовый URL — `https://hub.gigaschool.ru/api/v1/llm/v1`, модель — `GigaChat/GigaChat-3-Pro`. Значение ключа не передаётся в браузер, экспорт или API-статус. После изменения `.env` перезапуск не нужен: конфигурация перечитывается сервером. Не коммитьте `.env`.

Для прямого Cloud.ru: `LLM_BASE_URL=https://foundation-models.api.cloud.ru/v1`, `CLOUDRU_MODEL=Qwen/Qwen3.6-35B-A3B`; ключ задаётся через `LLM_API_KEY` либо `CLOUD_RU_FOUNDATION_MODELS_API_KEY`. Поддерживаются только явно разрешённые адреса сервисов, перенаправления запросов с ключом отключены. Контракт прямого API: [документация Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__specs).

База создаётся в `.local/metodist.sqlite3`, вне Git. Путь можно изменить: `.venv/bin/python -m backend.server --db /absolute/path/courses.sqlite3 --port 4173`. На выданной VM также распознаются OPENAI_API_KEY и OPENAI_BASE_URL; модель командного шлюза выбирается по умолчанию.

Для резервной копии остановите сервер и скопируйте файл базы. Запускайте один экземпляр сервера на одну базу.

## Основной сценарий

1. «Новая» → название, аудитория, тип и 16–500 часов. Создаётся отдельный сохранённый черновик; старые программы доступны в «Мои программы».
2. Укажите входной уровень, формат и аттестацию. «Сформировать каркас» или запрос в чате → цель, результаты с картой знаний/умений/навыков, модули и темы с часами по видам работы. Результаты и расписание готовятся отдельными вызовами модели. Сервер распределяет ровно заданный объём по весам видов работы методом наибольших остатков; весь план показывается до согласования. Ответ модели хранится как предложение; до принятия курс не меняется.
3. Просмотреть и применить пакет. Проверить часы и нажать «Согласовать каркас». Сервер проверяет этот переход отдельно от интерфейса.
4. «Подготовить материалы» → сервер готовит каждый модуль, затем предлагает весь комплект одним пакетом: учебное содержание с примерами, тесты с ключами и связями результатов, задания с критериями, планы лекций и редактируемые слайды. Глубина и предметная корректность требуют проверки экспертом. Применение атомарное.
5. Редактировать материалы вручную или запросить связанный пакет правок в чате. Принятые ручные правки сохраняются; несохранённые поля редактора защищены от случайного переключения. Изменение структуры снимает согласование и помечает прежние материалы как требующие обновления, сохраняя их текст.
6. «Экспорт» → DOCX комплекта, PPTX слайдов с планами в заметках, Moodle XML тестов, JSON сохранённой версии или печать текущего материала в PDF через браузер. В Moodle XML используются вопросы с открытым ответом (essay): ключи идут в graderinfo для преподавателя, проверка вручную.

Адрес `?course=<UUID>` открывает конкретную программу после перезагрузки. Статус фонового запуска и готовое предложение восстанавливаются. Перезапуск сервера переводит незавершённые запуски в ошибку, сохраняя курс. История чата между загрузками не сохраняется; сохраняются курс, предложения и состояния запусков.

При конфликте версий сервер отвечает 409 и не затирает более свежие данные. При недоступности сервера правки остаются в текущей вкладке: доступны повторное сохранение, резервный JSON и явное открытие сохранённой версии. Не закрывайте вкладку до сохранения или скачивания правок.

Ошибки ключа, лимита, сети, JSON, часов или полноты ответа модели не изменяют курс. У каждого запуска есть идентификатор; повтор того же запроса возвращает тот же запуск. Повторная попытка после ошибки — новый явный запуск, без автоматического повтора платных вызовов. Одновременно допускается один запуск на курс.

## Референсы и проверка источников

Кнопка скрепки читает TXT (UTF-8), DOCX и PDF с текстовым слоем. До 20 МБ на файл, 10 файлов на курс, 60 000 знаков на файл и 120 000 знаков суммарно. Перед сохранением методист просматривает извлечённый текст и подтверждает его использование. Оригиналы не хранятся; текст сохраняется в SQLite и передаётся только настроенному Cloud.ru/командному шлюзу. Сканы без текстового слоя, зашифрованные и повреждённые документы отклоняются. OCR не подключён. Таблицы PDF требуют визуального сравнения с оригиналом.

«Источники» хранит название, ссылку, статус и сведения о проверке. Подтверждение — ручная отметка методиста с обязательным пояснением. Модель не может выставлять её или менять список источников. Неподтверждённые записи не входят в литературу DOCX и остаются замечаниями. Существование внешних ссылок автоматически не проверяется; предметную корректность проверяет эксперт.

## API и воспроизводимость

Все запросы отправляются на тот же локальный origin; JSON, ошибки 422 (данные), 409 (конфликт), 503 (зависимость), 404 (не найдено).

- `POST /api/courses` с `{course: {...}}` создаёт курс; `GET /api/courses` возвращает список.
- `GET /api/courses/<id>` возвращает курс, revision, checks, job и proposal. Старые JSON-курсы получают новые необязательные поля при чтении без перезаписи базы.
- `PUT /api/courses/<id>` с `{revision, course}` сохраняет ручные правки.
- Единая точка запуска агента: `POST /api/courses/<id>/generate` с `{revision, stage, prompt, requestId}`. `stage`: `skeleton`, `materials`, `revision` или `module`; для `module` нужен `moduleIndex` (от нуля) и уже готовый согласованный комплект. Возвращается job; состояние опрашивается через GET курса. Пример payload: `{"revision": 0, "stage": "skeleton", "prompt": "Практический курс", "requestId": "unique-run-1"}`.
- `POST /api/courses/<id>/approve` с `{revision}` согласует валидный каркас: общие/тематические часы, карта и темы результатов.
- `POST /api/proposals/<id>/accept` с `{revision}` либо `/reject` с `{}` обрабатывает предложение. Успешный новый запуск заменяет прежнее ожидающее предложение. Модель не применяет результат самостоятельно.
- `POST /api/references/extract` с `{name, data}` (base64) возвращает `{name, text}` без сохранения. Подтверждённый текст добавляется в `course.references` обычным PUT с проверкой версии.
- `GET /api/courses/<id>/export.json|export.docx|export.pptx|export.moodle.xml` выгружает сохранённую версию. JSON имеет schemaVersion 3; содержит также checks и lastRun.

`job.metrics` содержит время запуска, токены usage от провайдера, число ответов с usage, attemptedCalls и usageComplete, а также оценку рублей по тарифам шлюза от 19.10.2026. При отсутствии usage значения не подменяются нулём. Оценка стоимости не является счётом провайдера. Неудачные ответы с usage тоже учитываются; если часть обращений не вернула usage, стоимость помечается как неполная. Автоматических платных повторов нет.

`Обновить модуль` вызывает модель только для выбранного модуля и заменяет его содержание, план, тесты, задания и слайды одним предложением. Остальные модули копируются без повторной генерации. Смена структуры снимает согласование; старые материалы сохраняются с признаком устаревания.

## Оставшиеся ограничения

- Две структуры DOCX различают повышение квалификации/стажировку и общеразвивающую программу, но точное совпадение с АЦР не подтверждено: ссылки на оба примера и пять тест-кейсов возвращают `ERR_BLOCKED_BY_CLIENT`. Нельзя считать это выполнением официальных чек-листов.
- Нормативные основания, действующие профстандарты/коды трудовых функций, календарные даты, оборудование, преподаватели и реквизиты утверждения требуют заполнения и проверки человеком. Шаблоны не подменяются выдуманными данными.
- Это однопользовательская локальная версия. Публичный режим — демонстрационный: посетители видят материалы всех программ, но не могут изменять их или запускать модель без пароля команды. Ролей и изоляции пользователей нет; для работы с закрытыми данными нужен отдельный защищённый контур. Публикация в GitHub не заменяет сдачу в Gitea.
- Текстовый слой PDF читается без OCR; формулы и сложные таблицы могут требовать ручной сверки.
- Автопроверка покрытия проверяет заявленные связи, а не смысловое соответствие вопроса результату. Требуется предметная экспертиза. Самооценка модели не является экспертной оценкой.

## Публичное демо на VM

Внешний запуск требует точного HTTPS origin и пароля команды длиной от 16 символов. Пароль передаётся в `METODIST_PASSWORD` через приватный EnvironmentFile сервиса (права 600); ключ модели — через OPENAI_API_KEY/OPENAI_BASE_URL выданной среды. Секреты не кладутся в Git и не передаются в аргументах процесса.

```sh
.venv/bin/python -m backend.server --host 0.0.0.0 --port 8000 --public-origin https://tochka-sborki-2026-team-109.hub.gigaschool.ru
```

Просмотр и скачивание открыты экспертам. Кнопка «Войти команде» даёт доступ к изменениям и генерации. Все POST/PUT, кроме входа/выхода, требуют серверной сессии. Cookie — HttpOnly, SameSite=Strict и Secure на публичном HTTPS; сессия действует 8 часов и сбрасывается при перезапуске. После 10 неверных паролей за минуту вход временно ограничивается. Проверки Host/Origin действуют и при входе. Пользователь без пароля получает 401, курс не меняется и LLM не вызывается.

Демо содержит только открытые учебные примеры. Не загружайте персональные или закрытые данные: чтение программ и референсов публично, предупреждение показано перед входом. Это защита расходов команды, а не многопользовательская авторизация или подтверждение соответствия эксплуатационным требованиям.

Для системного сервиса на выданной Linux VM: создайте venv, установите requirements.txt, передайте ключ модели штатными переменными среды, задайте приватно METODIST_PASSWORD и выполните:

```sh
.venv/bin/python deploy/install.py --origin https://tochka-sborki-2026-team-109.hub.gigaschool.ru
systemctl status metodist.service
```

Установщик запускается от пользователя команды, требует уже выданный `sudo -n` только для установки/перезапуска собственного systemd unit. Приложение работает от пользователя команды с ограничением записи в `.local/`, автоматически стартует после перезагрузки и перезапускается при падении. Секреты находятся в `~/.config/metodist/service.env` с правами 600, каталог — 700. Журнал: `journalctl -u metodist.service`. Перед заменой базы остановите именно этот сервис; исходные `data/`, `notebooks/` и другие процессы не затрагиваются.

## Проверка

```sh
.venv/bin/python -W error::ResourceWarning -m unittest discover -s backend/tests -v
cd frontend
npm test
npm run check
```

Бэкенд-тесты используют временную SQLite и контролируемый тестовый генератор: проверяют сохранение и повторное открытие, конфликты, старые ответы, согласование, атомарный пакет, недоступный ключ, неполные ответы, повтор запросов, восстановление запусков, HTTP Origin и экспорт OOXML. Они не подменяют проверку реального шлюза и браузерного сценария. Настоящая генерация вызывается только явным действием пользователя.

## Использованные библиотеки и визуальные ресурсы

Форматы: [pypdf](https://github.com/py-pdf/pypdf), [python-docx](https://github.com/python-openxml/python-docx), [python-pptx](https://github.com/scanny/python-pptx). Исходники и лицензии поставляются с пакетами. Интерфейс использует [Lucide](https://lucide.dev/) (лицензия в frontend/assets/LUCIDE-LICENSE.txt) и Golos Text (OFL в frontend/assets/OFL.txt).
